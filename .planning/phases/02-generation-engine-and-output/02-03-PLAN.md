<objective>
Create the Program.cs generator with conditional feature wiring and the architecture-specific project structure generator that produces the correct folder/file organization for Clean Architecture, Vertical Slice, and Simple Layered patterns.

Purpose: These are the core generators that produce the main runnable project structure. ProgramCsGenerator is the most complex template — it must conditionally include using statements, service registrations, and middleware for every feature combination. ArchitectureGenerator composes the other generators (CsprojGenerator, ProgramCsGenerator, AppSettingsGenerator) into a complete file dictionary for each architecture pattern.
Output: Two generator classes that together produce the main project structure for any configuration.
</objective>

**ProgramCsGenerator.cs** — Static class `ProgramCsGenerator` in `NetStarter.Services.Generation`. Method `string Generate(ProjectConfiguration config)` that returns the full Program.cs content.

Use private helper methods to build each section as a string (empty string if feature not selected):

1. `BuildUsings(config)` — Conditional using statements:
   - Always: none (implicit usings covers most)
   - If EF Core: `using Microsoft.EntityFrameworkCore;`
   - If JWT: `using Microsoft.AspNetCore.Authentication.JwtBearer;`, `using Microsoft.IdentityModel.Tokens;`, `using System.Text;`
   - If Serilog: `using Serilog;`
   - If OpenTelemetry: `using {Namespace}.Telemetry;` (or `using {Namespace}.Api.Telemetry;` for CleanArch) — imports the `AddAppOpenTelemetry` extension method from ObservabilityGenerator (Plan 02-04). No direct OpenTelemetry namespace usings needed in Program.cs.
   - If Mapster: `using Mapster;`, `using MapsterMapper;`

2. `BuildServiceRegistrations(config)` — Between `CreateBuilder` and `Build`:
   - If EF Core + PostgreSQL: `builder.Services.AddDbContext<AppDbContext>(options => options.UseNpgsql(builder.Configuration.GetConnectionString("DefaultConnection")));`
   - If EF Core + SQL Server: same but `UseSqlServer`
   - If JWT: Full `AddAuthentication(JwtBearerDefaults.AuthenticationScheme).AddJwtBearer(...)` with token validation parameters reading from config (as shown in RESEARCH.md code examples)
   - If Serilog: `builder.Host.UseSerilog((context, config) => config.ReadFrom.Configuration(context.Configuration).WriteTo.Console().WriteTo.File("logs/log-.txt", rollingInterval: RollingInterval.Day));`
   - If Health Checks: `builder.Services.AddHealthChecks();`
   - If OpenTelemetry: `builder.Services.AddAppOpenTelemetry(builder.Configuration);` — this calls the extension method generated by ObservabilityGenerator (Plan 02-04). Do NOT use inline `AddOpenTelemetry().WithTracing().WithMetrics()` setup. The extension method class (`OpenTelemetryExtensions.cs`) is always generated by ArchitectureGenerator when OTel is selected, so the call site in Program.cs can safely reference it. Add `using {Namespace}.Telemetry;` (or `{Namespace}.Api.Telemetry` for CleanArch) to the usings section.
   - If Mapster: `builder.Services.AddSingleton(TypeAdapterConfig.GlobalSettings);`, `builder.Services.AddScoped<IMapper, ServiceMapper>();`
   - For WebApi: `builder.Services.AddControllers();`
   - For MinimalApi: `builder.Services.AddEndpointsApiExplorer();`

3. `BuildMiddleware(config)` — Between `Build` and `Run`:
   - If JWT: `app.UseAuthentication();`, `app.UseAuthorization();`
   - If Health Checks: `app.MapHealthChecks("/health");`
   - For WebApi: `app.MapControllers();`
   - For MinimalApi: Add a sample endpoint: `app.MapGet("/api/hello", () => new { Message = "Hello from {config.ProjectName}!" });`

4. `BuildSampleEndpoint(config)` — One sample endpoint per user decision:
   - WebApi: Skip (sample controller handles it)
   - MinimalApi: Included in middleware section
   - Console: Different Program.cs entirely — just `Console.WriteLine`
   - WorkerService: Different Program.cs — `builder.Services.AddHostedService<Worker>();`

Handle Console and WorkerService project types with completely different Program.cs templates (they don't use `WebApplication`).

Use raw string literals with interpolation for clean template assembly. Per locked decision: minimal inline comments, only comment non-obvious things.

  <name>Task 2: Create ArchitectureGenerator for all three architecture patterns</name>
  <files>
    NetStarter/NetStarter/Services/Generation/ArchitectureGenerator.cs

  <action>
**ArchitectureGenerator.cs** — Static class `ArchitectureGenerator` in `NetStarter.Services.Generation`. Three public methods that populate a `Dictionary<string, string>` (path → content):

1. `void GenerateCleanArchitecture(ProjectConfiguration config, Dictionary<string, string> files, string root)` — Produces:
   - `{root}/src/{Name}.Domain/{Name}.Domain.csproj` — classlib with no extra packages
   - `{root}/src/{Name}.Domain/Entities/SampleEntity.cs` — if EF Core selected (sample entity with Id and Name)
   - `{root}/src/{Name}.Application/{Name}.Application.csproj` — classlib referencing Domain
   - `{root}/src/{Name}.Application/Mapping/MappingConfig.cs` — if Mapster selected
   - `{root}/src/{Name}.Infrastructure/{Name}.Infrastructure.csproj` — classlib referencing Application, with EF Core packages if selected
   - `{root}/src/{Name}.Infrastructure/Data/AppDbContext.cs` — if EF Core selected (DbContext with primary constructor pattern from research)
   - `{root}/src/{Name}.Api/{Name}.Api.csproj` — web project referencing Infrastructure, Application, with JWT/Serilog/OTel/HealthCheck packages
   - `{root}/src/{Name}.Api/Program.cs` — from ProgramCsGenerator
   - `{root}/src/{Name}.Api/appsettings.json` — from AppSettingsGenerator
   - `{root}/src/{Name}.Api/appsettings.Development.json` — from AppSettingsGenerator
   - `{root}/src/{Name}.Api/Auth/JwtSettings.cs` — if JWT selected (POCO class for JWT config binding)
   - `{root}/src/{Name}.Api/Telemetry/OpenTelemetryExtensions.cs` — if OTel selected (extension method for AddOpenTelemetry)
   - `{root}/src/{Name}.Api/Controllers/HelloController.cs` — if WebApi type (sample controller with [ApiController])

   For project references in .csproj: Infrastructure references Application (`..\{Name}.Application\{Name}.Application.csproj`), Application references Domain, Api references Infrastructure and Application.

2. `void GenerateVerticalSlice(ProjectConfiguration config, Dictionary<string, string> files, string root)` — Single project:
   - `{root}/src/{Name}/{Name}.csproj` — web project with all selected packages
   - `{root}/src/{Name}/Program.cs`
   - `{root}/src/{Name}/appsettings.json`, `appsettings.Development.json`
   - `{root}/src/{Name}/Features/` — empty (no generated feature files)
   - `{root}/src/{Name}/Data/AppDbContext.cs` — if EF Core
   - `{root}/src/{Name}/Data/Entities/SampleEntity.cs` — if EF Core
   - Auth, Mapping, Telemetry folders same pattern as CleanArch but inside single project

3. `void GenerateSimpleLayered(ProjectConfiguration config, Dictionary<string, string> files, string root)` — Single project:
   - Same structure as VerticalSlice but with Controllers/ (or Endpoints/ for MinimalApi) and Services/ and Data/ folders
   - `{root}/src/{Name}/Controllers/HelloController.cs` — if WebApi
   - `{root}/src/{Name}/Endpoints/HelloEndpoint.cs` — if MinimalApi (static class with MapGet extension)

Each architecture method calls `CsprojGenerator` for .csproj content, `ProgramCsGenerator` for Program.cs, and `AppSettingsGenerator` for config files. Generate actual file content (not placeholders) for all template files.

For Console and WorkerService project types: these always use SimpleLayered-style single project structure regardless of the Architecture setting (no multi-project for console apps). In that case, only generate the main project .csproj + Program.cs + any selected features. Add a `void GenerateConsoleOrWorker(...)` private helper.

NOTE: ArchitectureGenerator does NOT generate Aspire AppHost or ServiceDefaults projects. Those are handled directly by ProjectGenerationService (Plan 02-06) which calls `CsprojGenerator.GenerateAspireAppHostProject()`, `CsprojGenerator.GenerateAspireServiceDefaultsProject()`, `AspireGenerator.GenerateAppHostProgram()`, and `AspireGenerator.GenerateServiceDefaultsExtensions()`. ArchitectureGenerator only generates the core src/ project structure (Domain, Application, Infrastructure, Api etc). The SlnxGenerator (Plan 02-02) already includes Aspire project paths in the .slnx when `IncludeDotNetAspire` is true.
