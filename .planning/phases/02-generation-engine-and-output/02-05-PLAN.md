**DockerGenerator.cs** — Static class in `NetStarter.Services.Generation`. Methods:

1. `string GenerateDockerfile(ProjectConfiguration config)` — Multi-stage Dockerfile following research pattern:
   - Base image: `mcr.microsoft.com/dotnet/aspnet:{major}.0` where major matches SDK version (8, 9, 10)
   - Build image: `mcr.microsoft.com/dotnet/sdk:{major}.0`
   - Non-root user: `USER $APP_UID` in base stage
   - EXPOSE 8080
   - For Clean Architecture: COPY all .csproj files individually for layer caching, then full COPY and build the Api project
   - For single-project (VerticalSlice/SimpleLayered): simpler COPY pattern
   - Publish with `/p:UseAppHost=false`
   - ENTRYPOINT `["dotnet", "{ProjectName}.Api.dll"]` for CleanArch, `["dotnet", "{ProjectName}.dll"]` for others
   - For Console/Worker: use `mcr.microsoft.com/dotnet/runtime:{major}.0` instead of aspnet

2. `string GenerateDockerCompose(ProjectConfiguration config)` — docker-compose.yml:
   - App service building from Dockerfile with port mapping 8080:8080
   - If EF Core + PostgreSQL: postgres service with `postgres:16-alpine`, volumes, environment vars matching appsettings connection string
   - If EF Core + SQL Server: `mcr.microsoft.com/mssql/server:2022-latest` with SA_PASSWORD and ACCEPT_EULA
   - App depends_on database service if database exists
   - Use YAML string (not a YAML library) since the structure is simple and predictable

Use raw string literals for Dockerfile/YAML content. No parsing libraries needed.

**TestProjectGenerator.cs** — Static class in `NetStarter.Services.Generation`. Methods:

1. `string GenerateSampleUnitTest(ProjectConfiguration config)` — One passing sample test per locked decision:
```csharp
namespace {Namespace}.Tests;

using FluentAssertions;

public class SampleTests
{
    [Fact]
    public void Sample_ShouldPass()
    {
        var result = 1 + 1;
        result.Should().Be(2);
    }
}
```

2. `string GenerateIntegrationTest(ProjectConfiguration config)` — Testcontainers integration test:
   - If PostgreSQL: Use `PostgreSqlContainer` from `Testcontainers.PostgreSql`
   - If SQL Server: Use `MsSqlContainer` from `Testcontainers.MsSql`
   - Template:
```csharp
namespace {Namespace}.IntegrationTests;

using Testcontainers.PostgreSql; // or MsSql
using Microsoft.EntityFrameworkCore;

public class DatabaseIntegrationTests : IAsyncLifetime
{
    private readonly PostgreSqlContainer _container = new PostgreSqlBuilder().Build();

    public async Task InitializeAsync() => await _container.StartAsync();
    public async Task DisposeAsync() => await _container.DisposeAsync();

    [Fact]
    public async Task Database_ShouldConnect()
    {
        var options = new DbContextOptionsBuilder<AppDbContext>()
            .UseNpgsql(_container.GetConnectionString())
            .Options;
        await using var context = new AppDbContext(options);
        var canConnect = await context.Database.CanConnectAsync();
        canConnect.Should().BeTrue();
    }
}
```
   - Adjust using statements and container type based on config.Database value
   - Include `using {Namespace}.Infrastructure.Data;` for CleanArch, `using {Namespace}.Data;` for others (to reference AppDbContext)
